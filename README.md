# seed-vigor-gate

`seed-vigor-gate` 是面向种质资源保藏技术员与发芽试验复核员的本地工作台。系统把种子批次登记、试验方案冻结、重复组布置、逐日观测、异常定向复测、规则判定、人工复核和资格凭据封存连接为一条可追溯流程。

浏览器页面与 JSON API 均由同一个 Go 服务提供，不需要 Node 或外部数据库。业务变更携带 `expectedVersion` 和 `Idempotency-Key`；本地事件账本使用连续聚合序号和 SHA-256 前序摘要链，提交成功前执行 `Sync`。服务重启时会重放账本并校验序号、哈希链、快照索引和已封存凭据。

## 构建

需要 Go 1.22 或更高版本：

```bash
go build ./cmd/seedgate
```

## 运行

默认仅监听高位回环地址 `127.0.0.1:19081`，数据保存在 `./data`：

```bash
go run ./cmd/seedgate -addr=127.0.0.1:19081 -data=./data
```

然后在浏览器打开 `http://127.0.0.1:19081/`。页面可完成从批次建档到凭据校验的全部操作。

也可以只设置端口号：

```bash
PORT=19123 go run ./cmd/seedgate
```

`PORT` 会绑定为 `127.0.0.1:<PORT>`。`-addr` 仅接受 `127.0.0.1`、`localhost` 或 `::1` 的明确高位端口，避免服务意外暴露到外部网络。

## 正常业务流程

1. 登记批次标识、物种、收获年份、预处理边界和送检数量。
2. 编制重复组、温度、观察日程、终止日及资格阈值并冻结方案快照。
3. 按快照布置全部重复组，通过样本边界和缺组检查后开始观测。
4. 按日录入分类计数；既可逐组修订，也可按冻结日程对同一观察日的多个有效组执行整批预检和原子提交。整批命令只推进一个聚合版本，任一行失败时不保存任何一组。
5. 自动趋势区仅采用各组各日最新修订，按日显示覆盖数、平均正常发芽率、增量、缺失组和离群定位提示；提示只用于复核，不改变资格规则。
6. 必要时登记污染、温控中断或计数失效异常。异常可同时选择多个有效组，系统先按送检量、原始布置量和复测耗用量核验余量，再为每个来源组创建一个定向复测组。复测全观察日齐备且指标已重算后才能闭环。
7. 计算最终发芽率、重复组离散度、阈值到达日和稳定排序的规则明细。
8. 复核退回至少登记一个方案、观测、异常或规则明细类事项。技术员通过原流程补充证据并重新计算后，可逐项填写完成说明；所有事项解决后才能再次送审和批准。
9. 批准后一次性封存资格凭据。在同一页面按凭据编号重算并固定顺序显示凭据内容、冻结方案、有效输入、事件链和复核材料五项一致性报告。

所有写命令都使用 `Idempotency-Key`，并携带当前 `expectedVersion`。批量观测重复提交同一幂等键时返回首次回执；版本冲突会返回当前聚合版本且不会产生部分观测。页面展示的样本余量、趋势、退回事项和凭据报告均来自当前评定详情投影，观测修订、异常作废、复测补录或重新计算后会即时重建。

## 测试与自检

运行全部单元和 HTTP 测试：

```bash
go test ./...
```

运行有界 selfcheck。该命令会使用指定的真实回环监听器，通过 HTTP API 完成正常流程、校验凭据、关闭服务，再重新打开临时账本验证恢复，最后自行退出：

```bash
go run ./cmd/seedgate selfcheck -addr=127.0.0.1:19081
```

## 本地数据

`-data` 指定的目录包含：

- `events.jsonl`：带 `schemaVersion`、聚合序号、前序摘要和事件摘要的只追加账本。
- `snapshot.json`：通过临时文件 `Sync` 后原子 `Rename` 更新的查询投影检查点。

账本、快照或已封存凭据出现摘要不符时，服务会拒绝带病启动。请在备份数据目录后再进行迁移或人工检查，不要直接编辑这些文件。
